**Cursor**

根据 `specs/001-ai-drama-stage/spec.md` 中的需求，特别是涉及到**多角色轮流对话（Orchestration）**、**流式输出**、**会话持久化**以及**MVP 快速验证**的目标，我推荐以下技术栈。

这个方案旨在**开发效率**（快速达成 MVP）与**用户体验**（实时流式响应）之间取得平衡。

### 推荐核心技术栈：Modern Full-Stack TypeScript

使用全栈 TypeScript 可以让你在前端和后端复用类型定义（User, DramaSession, Turn），减少上下文切换，非常适合此类 CRUD + AI 逻辑的应用。

#### 1. 前端框架 (Frontend)
*   **Next.js (App Router)**: 目前构建 AI 应用的首选。
    *   **理由**:
        *   **React Server Components (RSC)**: 适合快速渲染初始页面（如历史列表）。
        *   **API Routes / Server Actions**: 可以直接在 Next.js 中编写后端逻辑（处理对话轮次、保存数据），无需额外部署后端服务。
        *   **Vercel AI SDK 集成**: Next.js 与 Vercel AI SDK 结合极其紧密，处理流式传输（Streaming）非常简单。

#### 2. UI 组件库 (UI Components)
*   **Tailwind CSS + shadcn/ui**:
    *   **理由**: `shadcn/ui` 提供了高质量的、类似 AI 产品的极简设计风格组件（Card, Dialog, ScrollArea），可以直接以此搭建“剧本编辑器”和“聊天气泡”界面，极大缩短 UI 开发时间。

#### 3. AI 编排与集成 (AI Orchestration)
*   **Vercel AI SDK (Core)**:
    *   **理由**: 针对 **SC-002 (响应速度)**，该 SDK 专为流式文本（Streaming Text）设计。它能让你在前端极易实现“打字机效果”，这对“观看演出”的体验至关重要。
*   **LangChain.js (可选，用于复杂逻辑)**:
    *   **理由**: 用于 **FR-006 (AI 辅助生成角色)**。LangChain 擅长管理 Prompt 模板（PromptTemplate），可以将用户的自然语言描述转化为结构化的 JSON 或特定格式的角色设定。对于多角色对话管理，也可以利用其 `ChatHistory` 抽象。
*   **Model Provider**: **OpenAI (GPT-4o-mini)** 或 **Anthropic (Claude 3.5 Sonnet)**。
    *   **理由**: MVP 阶段直接调用 API。GPT-4o-mini 成本低且速度快，适合高频的多轮对话；Claude 在角色扮演（Roleplay）上通常表现更自然。

#### 4. 数据库与 ORM (Database)
*   **PostgreSQL (e.g., Supabase / Neon)**:
    *   **理由**: 你的数据模型（User, SceneTemplate, RoleTemplate, DramaSession, Turn）是典型的高度关联关系型数据。Postgres 的 `JSONB` 字段也非常适合存储结构灵活的 Prompt 设定。
*   **Prisma**:
    *   **理由**: TypeScript 生态中最好的 ORM。它能根据数据库 Schema 自动生成 TS 类型，确保你在编写业务逻辑时不会弄错字段（比如 `Turn` 的 `content` 字段）。

#### 5. 状态管理与即时通讯 (State & Realtime)
*   **SWR / TanStack Query**: 用于前端数据获取（如加载历史演出列表）。
*   **Server-Sent Events (SSE)**: Vercel AI SDK 默认使用。
    *   **理由**: 相比 WebSocket，SSE 更轻量，足以处理 **FR-002** 中的文本流式输出。

### 针对特定需求的架构映射

| 需求点 | 推荐技术方案 | 实现思路 |
| :--- | :--- | :--- |
| **FR-002 (多角色轮流)** | **Next.js Server Actions** | 在后端维护一个“状态机”。当用户点击“开始”或上一轮结束时，触发 Action -> 读取当前 Session -> 判断该谁说话 -> 组装 Prompt (场景+人设+历史) -> 调用 LLM -> 流式返回前端 -> 存入 DB。 |
| **FR-012 (中断恢复)** | **PostgreSQL + Prisma** | 每一轮（Turn）生成完毕后，立即写入 `Turn` 表。`DramaSession` 表记录 `current_turn_index`。用户刷新页面时，SSR 读取 DB 中的完整历史并渲染。 |
| **FR-006 (AI 生成角色)** | **OpenAI Structure Output / Zod** | 使用 LLM 的 Structured Output (JSON mode) 功能。用户输入自然语言 -> LLM 输出符合 `RoleTemplate` Schema 的 JSON -> 前端填充表单供用户修改。 |
| **SC-002 (低延迟)** | **Vercel AI SDK (useChat / useCompletion)** | 利用 `streamText` 函数，将 AI 的 token 逐个推送到前端，用户无需等待整段生成即可看到内容。 |

### 备选方案（如果不使用 Next.js）

如果你更熟悉 Python，或者未来打算引入本地 LLM / 复杂的 Agent 逻辑（如让 AI 自己决定谁先说话，而不是固定轮次）：

*   **Backend**: **FastAPI (Python)** + **LangGraph** (专门用于构建多 Agent 状态机)。
*   **Frontend**: **React (Vite)**。
*   **缺点**: 需要维护两个项目（前端+后端），部署稍复杂，类型共享不如全栈 TS 方便。

### 总结建议

对于 **MVP** 和 **001-ai-drama-stage** 的规模，**Next.js + Vercel AI SDK + PostgreSQL (Prisma)** 是最快落地的路径。

你可以从定义 Prisma Schema 开始（User, Scene, Role, Session, Turn），然后直接用 Next.js API 编写“导演”逻辑。
