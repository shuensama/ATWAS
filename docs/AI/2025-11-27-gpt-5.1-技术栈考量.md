## 总体建议

**做成一个典型 Web 应用：前后端一体，TypeScript 优先**。  
在你这份规格的复杂度下，我会优先推荐：

- **前后端同构框架**：Next.js（React + TypeScript，App Router）
- **后端能力**：用 Next.js 的 API Route / Server Actions 实现「多 AI 演员轮流对话编排」
- **数据库**：PostgreSQL + Prisma ORM
- **大模型调用**：OpenAI / 任意兼容 OpenAI API 的模型服务
- **部署**：Vercel / Railway / Render 等一键部署平台（MVP 足够）

---

## 为什么这套栈契合你这份规格

- **多 AI 演员轮流对话编排（FR-001 ~ FR-003, FR-008, FR-012）**
  - **Next.js API Route + TypeScript**：写一个 `orchestrator` 服务，按 `DramaSession` 的配置（角色顺序、轮数）循环调用大模型，每一轮记录成 `Turn`，非常适合在 Node 环境里做。
  - TypeScript 对你这套实体（`SceneTemplate` / `RoleTemplate` / `DramaSession` / `Turn`）建模很自然，对以后维护和扩展也友好。

- **历史会话 & Prompt 库持久化（FR-004 ~ FR-007, FR-011 ~ FR-013）**
  - **PostgreSQL + Prisma**：  
    - `User`, `SceneTemplate`, `RoleTemplate`, `DramaSession`, `Turn` 这些都是典型关系型结构。
    - Prisma schema 可以直接用你 spec 里的字段建模，并且支持复杂查询（按标签、名称、最近使用排序等）。
  - 长期存历史记录（Assumptions 里已说明）对关系型数据库很友好，后期要做统计分析也方便。

- **AI 生成角色流程（FR-006）**
  - 同样通过 **Next.js API Route** 封装一条「角色生成」接口：  
    - 输入：用户的自然语言描述  
    - 输出：结构化的角色 prompt（JSON）  
  - 利用 TypeScript 类型，对前后端的数据结构保持完全一致，前端表单可以直接复用类型。

- **前端 UI 需求**
  - **React + Next.js** 很适合做：
    - 多角色轮番发言的对话区（气泡流 / 剧本视图）
    - 配置向导（选择场景、添加角色、配置轮数）
    - 历史列表页 / 详情页
    - Prompt 库管理页（搜索、筛选、预览）
  - 可以选：
    - **组件库**：Ant Design / MUI / Mantine  
    - **样式**：Tailwind CSS（快速迭代 MVP 很合适）

- **性能与体验（SC-002）**
  - 文本对话为主、不要求语音视频，对服务器压力相对有限。
  - Next.js + Node 对并发调用 OpenAI API 是成熟场景，通过合理的流控及缓存可以满足「大多数 5 秒内返回」的体验要求。

---

## 更细一点的关键组件选型

- **状态管理 & 数据获取**
  - **React Query / TanStack Query**：处理会话列表、Prompt 库、正在进行的 `DramaSession` 拉取/更新，都很顺手。
  - 简单的播放控制状态（暂停/继续/下一轮）可以放在组件本地 state 或 Zustand 之类轻量状态库。

- **用户体系**
  - 如果不想一开始自己实现登录注册：
    - 用 **Supabase Auth** / **Clerk** / **Auth0**，都与 Next.js 集成良好。
  - 自己实现的话，用 NextAuth 也可以。

- **大模型编排工具（可选）**
  - 简单 MVP 直接自己写调用逻辑即可。
  - 若后续要做更复杂的「多代理」逻辑，可以考虑：
    - LangChainJS / LangGraph（在 Node/TS 环境下用）  
    - 但第一版可以完全不依赖这些，只做「顺序调 OpenAI」。

---

## 如果团队更偏 Python

若你们团队完全是 Python 背景，也可以选择：

- **后端**：FastAPI + SQLModel / SQLAlchemy + PostgreSQL  
- **前端**：Vue 3 + Vite 或 React + Vite  
- 编排逻辑放在 FastAPI 中实现，多 AI 发言轮次逻辑一样好做。  
只是前后端分离，相比 Next.js 一体化稍微多一些工程整合工作。

---

## 总结一句话

**如果没有强烈的语言偏好，推荐：Next.js（React + TS） + Node API 编排大模型 + PostgreSQL + Prisma**，这套栈几乎零阻力支持你规格里的所有需求（多 AI 轮流演出、Prompt 模板库、历史会话持久化和恢复），同时对 MVP 开发和后续扩展都比较省心。
