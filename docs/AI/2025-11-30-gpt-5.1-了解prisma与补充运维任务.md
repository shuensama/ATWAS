## 总体在干什么？

这几条任务（T006–T010）本质上是在**把你的关系型数据模型，用 Prisma 搭好完整的一套「数据库访问层」**：

1. 用 `prisma/schema.prisma` 定义表（Prisma 里叫 `model`）和索引  
2. 生成一个可复用的 Prisma 客户端（代替你手写 SQL）  
3. 用「仓储（Repository）」封装具体表的 CRUD  
4. 跑首次迁移，把模型真正同步到数据库里  

你已经会 SQL / 关系型数据库，可以把 Prisma 理解成：  
**“用 TypeScript + 一个 schema 文件来描述表，然后自动帮你生成 SQL + TypeScript 客户端”** 的 ORM。

---

## Prisma 基本概念（跟 SQL 的对应关系）

- **`schema.prisma`**：相当于「数据库建表 SQL 的声明版」
  - 你在这里写：

    ```prisma
    model User {
      id        Int      @id @default(autoincrement())
      email     String   @unique
      createdAt DateTime @default(now())
      // ...
    }
    ```

  - Prisma 会根据它生成迁移 SQL（`CREATE TABLE ...`、`CREATE INDEX ...`）

- **Prisma Client**：自动生成的 TypeScript 客户端  
  - 让你在代码里写：

    ```ts
    const user = await prisma.user.findUnique({ where: { id: 1 } });
    ```

  - 而不是自己写 `SELECT * FROM "User" WHERE "id" = 1`

- **迁移（migrations）**：  
  - 把 `schema.prisma` 的变化真正执行到数据库（创建/修改表、索引）

### T007：创建 Prisma Client 单例

> 创建 `lib/db/client.ts`，实现基于 `DATABASE_URL` 的 Prisma Client 单例，并在其中加载 `prisma/schema.prisma`。

  - 以后所有代码都从这里拿 `prisma` 来查表，不各自 new

- **从 SQL 视角看**：

> 在 `lib/db/repositories/scene-template-repository.ts` 与 `lib/db/repositories/role-template-repository.ts` 中实现基础 CRUD 仓储。

  - 让业务层不用关心 Prisma 的细节，而是调用「仓储」方法

- **从 SQL 视角看**：  
  - 相当于写了一层 `DAO / Repository`，里面用 Prisma 代替你写 `SELECT/INSERT/UPDATE/DELETE`。

### T010：跑第一次 Prisma 迁移

> 运行 `npx prisma migrate dev`，让数据库 schema 跟 `schema.prisma` 对上。

- **在做的事**：
  - Prisma 会：
    - 根据 `schema.prisma` 生成迁移 SQL 文件，放进 `prisma/migrations/`
    - 执行这些 SQL 到真实数据库
  - 执行完之后，你的数据库里就真的有上面这些表和索引了

- **从 SQL 视角看**：  
  - 等价于：写了一堆 `CREATE TABLE ...` + `CREATE INDEX ...` 的脚本并执行，还把脚本版本化保存下来。

  - 通过 `DATABASE_URL` + `new PrismaClient()`，底层管理连接池、执行 SQL  
  - 你只写 TypeScript 调用 `prisma.xxx`，Prisma 帮你拼 SQL、发给 Postgres

- **宗旨是让后端程序更容易、安全地用数据库**：  
  - 提供**类型安全**（TS 自动推类型，少写错字段名 / 类型）  
  - 提供**更简洁的 API**（`findMany / create / update` 等）  
  - 提供**迁移系统**，用版本化的方式管理表结构变化，而不是散落 SQL 脚本

可以把 Prisma 理解成：**一个帮你把「关系型数据库 + SQL」打包成「TypeScript 对象 + 函数」来用的 ORM 工具**。
