### 概念先搞清

- **ESLint 是什么？**  
  - 一句话：**JavaScript/TypeScript 的“代码质量/规范检查工具”**。  
  - 主要做的事：  
    - 找 bug：如未使用的变量、潜在的逻辑错误、异步问题等。  
    - 限制风格以外的“坏习惯”：比如禁止 `any`、必须用 `===` 等。  
    - 可自定义规则、继承别人写好的规则集（如 `eslint:recommended`、`next/core-web-vitals` 等）。

- **Prettier 是什么？**  
  - 一句话：**“代码自动美化/格式化工具”**。  
  - 主要做的事：  
    - 自动统一格式：缩进、引号单双、分号要不要、行宽、括号换行等。  
    - 只关心“长得好不好看、一不一致”，**不评价代码逻辑对不对**。  
    - 支持多种语言：JS/TS、JSON、Markdown、CSS、HTML 等。

---

### 二者的区别与配合方式

- **关注点不同**  
  - ESLint：**代码对不对、好不好**（质量、潜在 bug、最佳实践）。  
  - Prettier：**代码漂不漂亮、一不一致**（格式、排版）。

- **如何一起用（现代项目常见做法）**  
  - 用 **Prettier 专门管格式**：保存文件时自动 format。  
  - 用 **ESLint 管逻辑和“非格式类”规范**：  
    - 禁用 ESLint 里跟“格式”相关的规则（由 Prettier 接管），常见做法是装 `eslint-config-prettier`。  
  - 结果：  
    - Prettier 负责“长什么样”；  
    - ESLint 负责“是不是好代码”。

---

### 总结

- **ESLint = 代码质量/规范检查器（Linter）**  
- **Prettier = 代码格式化工具（Formatter）**  
- 现代前端项目里，**通常两个都会用**：一个保质量，一个保统一格式。

### 1. 在命令行里怎么用

在项目根目录 `e:\AI\ATWAS` 下：

- **运行 ESLint 检查代码：**

```bash
npm run lint
```


这两个脚本已经在你的 `package.json` 里定义好了：

---

### 2. 在 VS Code 里配合使用（推荐）

最舒服的用法是：**保存文件时自动 Prettier 格式化，同时 ESLint 实时提示问题**。

大致步骤（只需要做一次）：

1. 安装插件：  
   - VS Code 扩展里装 **ESLint**  
   - VS Code 扩展里装 **Prettier - Code formatter**

2. 设置「保存自动格式化」和让 Prettier 当默认格式化器（`settings.json` 大概是这样的）：

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}
```

3. 让 ESLint 实时提示：  
   安装好 ESLint 插件后，保存文件或打开文件时，它会自动根据 `.eslintrc.cjs` 提示错误/警告。

---

### 3. 实际工作流怎么用？

日常写代码时：

- **边写：**  
  - VS Code 左边/底部会出现 ESLint 的红线/黄线，提示潜在问题。  
- **保存：**  
  - Prettier 自动把缩进/引号/分号等排好版。  
- **提交代码前：**  
  - 跑一遍 `npm run lint` 检查有没有 ESLint 错误。  
  - 如果需要，跑 `npm run format` 全量格式化一次。

### 什么时候「适合」用 Prettier 格式化文档？

**适合用**（建议开启）的情况：

- 很多 `.md`、`.yaml`（比如 OpenAPI）文档，团队多人一起写，希望：
  - 行宽统一（比如 80 列）
  - 标题、列表、代码块的缩进风格统一
  - 表格、列表不因为编辑器换行而变乱
- 这些文档**不是自动生成的**，而是你们手写、长期维护的规范/设计文档（你现在的 `specs/`、`docs/AI` 就是这种）。

**不太建议**用 Prettier 的情况：

- 文档里有一些「对空格特别敏感」的内容：
  - 特殊 ASCII 图形、对齐好的表格、手写的时序图等  
  - 某些工具会自己生成/格式化（你只当成“输出结果”看的），这类文件一般交给工具本身处理。

---

### 针对你这个项目的建议
